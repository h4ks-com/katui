# katui: agent guide

Graphics-first terminal UI engine in Rust: cell and pixel planes over the
kitty graphics protocol, ratatui-compatible, portable fallbacks. The crate
map, seams and test rules live in [ARCHITECTURE.md](ARCHITECTURE.md). Read
it before writing code; it is the contract this guide enforces.

## Layout

The crate map lives in [ARCHITECTURE.md](ARCHITECTURE.md). Outside
`crates/`: `bindings/python/` is the `katui` Python package (PyO3, built
with maturin); `bindings/c/` is the C ABI (`katui-c`, header generated by
cbindgen); `bindings/go/` is the Go module over that C ABI (cgo);
`bindings/node/` is the `katui` npm package (napi-rs);
`demos/obby-chat/` is an IRC client on the full engine, GPL and
outside the workspace; `scripts/` holds repo tooling (the commit-message
gate); `.opencode/` holds repo commands and skills.

## Commands (the justfile is the single source of truth)

- `just check`: clippy with CI's denials; run after every change
- `just ci`: the gate; must pass before any commit
- `just fix`: clippy --fix + fmt, the mechanical repairs
- `just test`: unit tests
- `just deny` / `just typos` / `just dupes` / `just machete`: the extra CI
  gates (licenses and advisories, spelling, copy-paste duplication, unused
  dependencies)
- `just metrics`: per-function complexity report via rust-code-analysis
  (`cargo install rust-code-analysis-cli` once). Report tier only; the
  gate tier stays clippy's cognitive ceiling of 20
- `just hooks`: install the prek hooks, once per clone
- `just py-check`: the Python package's gates (ruff, strict mypy,
  stubtest, pytest); part of `just ci`, needs uv. `just py-fmt` applies
  ruff's fixes, `just py-demo <name>` runs a Python example
- `just c-check`: the C library's gates (fresh header, examples, C tests,
  docs, sync); part of `just ci`, needs cbindgen and a C compiler.
  `just c-header` regenerates `bindings/c/include/katui.h`, `just c-demo
  <name>` runs a C example
- `just go-check`: the Go module's gates (vet, gofmt, tests, docs, sync);
  part of `just ci`, needs Go. `just go-demo <name>` runs a Go example
- `just node-check`: the Node package's gates (fresh generated types,
  strict tsc, biome, node:test); part of `just ci`, needs Node 22.18 or
  newer. `just node-fmt` applies biome's fixes, `just node-demo <name>`
  runs a Node example
- CI (`.github/workflows/ci.yml`) runs `just ci`'s checks plus deny, dupes
  and machete, which `just ci` skips, and a raw `cargo check` on the MSRV.
  Never run a raw tool in CI when a just target exists for it.

## The loop

1. Keep the change small; one concern per commit.
2. `just check` after every change, `just ci` before committing.
3. Review every non-trivial change before committing
   (`.opencode/skill/review/`). Fix Critical and Important findings first.
4. Commit with `git commit`. The prek hooks run fmt, clippy and the
   commit-message gate. If a hook fails, fix the cause. Never commit with
   `--no-verify`.
5. Commit messages: one conventional line, `<type>: <lowercase imperative
   summary>` with types feat, fix, perf, refactor, test, docs, chore, ci,
   build, revert; e.g. `feat: chunk kitty payloads at 4096 bytes`.

## Rules

- Work stays inside this repository. Never modify, branch, build in, or
  run tests in another repository on this machine, even a scratch branch,
  unless the user asks for exactly that in the current session.

- Code is done only when `just ci` passes. Run it, don't assume.
- No `unwrap`, `panic!` or `todo!` in non-test code; clippy denies them.
  `expect` needs a reason. `unsafe` is denied workspace-wide.
- Errors: one typed `thiserror` enum per crate. No `Result<_, String>`
  seams.
- Cognitive complexity over 20 fails CI (clippy.toml): the function grew a
  second job, split it.
- Layering follows the rules in ARCHITECTURE.md: terminal bytes come from
  encoders, presenters and the runtime only; proto, scene and present know
  nothing about widgets; only katui-rt performs I/O.
- Unit-testable means no terminal. Encoders get golden-byte tests, parsers
  get fuzzing and recorded-reply fixtures, the scene gets diff invariants.
  A module lands only with tests and an artifact a human can look at:
  bytes, a scene dump or a PNG.
- New dependencies: declare once in `[workspace.dependencies]` and justify
  in the commit. Copyleft stays out
  of the build graph; cargo-deny enforces the license list.
- Comments explain why, never what; default to zero. No change-history
  commentary.
- Prose in docs, commits and comments: declarative, terse, no em dashes.
- Nothing personal in the repo: no real names, handles, emails, local
  machine paths or assistant attribution in code, docs, fixtures, commit
  messages or CI. Test data uses generic mock names ("acme", "reviewer").
- `research/` is git-excluded local scratch. Tracked files never reference
  it or any local path; everything a cold reader needs lives in tracked
  docs or a public URL.
- The Rust API is the source of truth for the Python package. A change to
  a public Rust item lands with its binding in `bindings/python/src`, the
  stub `_katui.pyi`, and the Python guide and examples it affects, or with
  an `OMITTED` entry in `tests/test_sync.py` that says why Python does
  without it. `just py-check` fails until one of them is done.
- The same holds for C and Go: the change lands with its C binding in
  `bindings/c/src` and the regenerated header, and its Go wrapper in
  `bindings/go`, or with an `OMITTED` entry in `bindings/c/tests/sync.py`
  and an `omitted` entry in `bindings/go/sync_test.go`. `just c-check` and
  `just go-check` fail until then.
- The same holds for the Node package: the binding in `bindings/node/src`,
  the regenerated `index.js` and `index.d.ts`, the Node guide and examples,
  or an `OMITTED` entry in `bindings/node/tests/sync.test.ts`.
  `just node-check` fails until one of them is done.
- `unsafe` is allowed in `bindings/c` and `bindings/node` only, where the
  foreign function interfaces need it.
- Do not weaken a gate to make it pass. Fix the code, or change the rule in
  a commit of its own with the argument.

## Secrets

The repo holds none. Keep it that way: no tokens in code, docs, CI or
fixtures.
